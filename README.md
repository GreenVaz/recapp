# Фінансовий календар

Персональний застосунок для планування фінансів. Головне питання, на яке
він відповідає: **скільки грошей буде на рахунку будь-якого дня** — з
урахуванням зарплат, регулярних платежів, кредитів і розстрочок.

Mobile-first PWA: встановлюється на екран «Домівка» iPhone і працює як
звичайний застосунок.

---

## Що вміє

**Фінансовий календар.** Місячна сітка, де кожен день показує надходження,
витрати, кредитні платежі та прогнозований залишок на кінець дня. Дотик
відкриває деталізацію: початковий баланс, список операцій, підсумок.

**Прогноз.** Горизонти 7 днів / 30 днів / 3 / 6 / 12 місяців. Для кожного —
очікувані доходи й витрати, мінімальний залишок, дати дефіциту, найбільші
майбутні витрати. Прогноз будується лише з підтверджених запланованих
операцій, регулярних правил і графіків кредитів — застосунок не вигадує,
що минула витрата обов'язково повториться.

**Рахунки.** Картки, банківські рахунки, готівка, ощадні рахунки в UAH /
USD / EUR. Переказ між власними рахунками не рахується доходом чи витратою.
Коригування залишку записується окремою операцією, тож історія завжди
пояснює поточний баланс.

**Кредити та розстрочки.** Ануїтет, диференційований графік, безвідсоткова
розстрочка, рівні платежі за відомою загальною сумою, ручний графік.
Дострокове й часткове погашення, скорочення строку або платежу, скасування
помилкового платежу. Для кожного кредиту: залишок тіла, переплата, відсоток
погашення, дата закриття.

**Регулярні операції.** Щодня / щотижня / щомісяця / щороку. Правка одного
повторення серії окремо від решти. Для платежів 29–31 числа — вибір, що
робити в коротких місяцях.

**Аналітика.** Структура витрат за категоріями, доходи проти витрат,
динаміка залишку, боргове навантаження. Фактичні дані й прогноз показані
окремо й ніколи не змішуються.

## Швидкий старт

### Локально

```bash
npm install
cp .env.example .env     # за бажанням — працює і без цього
npm run dev              # http://localhost:5173
```

Без `DATABASE_URL` застосунок піднімає **PostgreSQL у пам'яті** (PGlite) —
та сама СУБД і ті самі міграції, тільки дані зникають після зупинки.
Цього досить, щоб усе спробувати, не заводячи жодного зовнішнього сервісу.

### З постійною базою

1. Створіть безкоштовний проєкт на [neon.tech](https://neon.tech) (або
   будь-який PostgreSQL 13+).
2. Впишіть рядок підключення в `.env`:
   ```
   DATABASE_URL="postgresql://…?sslmode=require"
   AUTH_SECRET="…"   # node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
   ```
3. `npm run dev`

Міграції застосовуються автоматично при першому запиті. Запустити їх
заздалегідь: `npm run db:migrate`.

## Розгортання

Застосунок розрахований на **Vercel + Neon**, обидва на безкоштовних тарифах.

1. **База.** У Vercel відкрийте проєкт → **Storage** → **Create Database** →
   **Neon** → план **Free**. Vercel сам додасть `DATABASE_URL` у змінні
   середовища проєкту.

   Альтернатива: створіть базу на neon.tech і додайте `DATABASE_URL`
   вручну в **Settings → Environment Variables**.

2. **Секрет сесій.** Додайте `AUTH_SECRET` — будь-який рядок від 32 символів:
   ```bash
   node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
   ```

3. **Деплой.** Vercel підхоплює кожен push у гілку. Збірка —
   `npm run build`, вихідна тека — `dist`, API — одна serverless-функція
   `api/index.ts`.

Схема бази створюється сама при першому запиті до API — окремого кроку
міграції в пайплайні не потрібно.

### Необов'язкове: відновлення пароля листом

Додайте `RESEND_API_KEY` ([resend.com](https://resend.com), 3000 листів на
місяць безкоштовно) і `APP_URL`. Без цього ключа застосунок повністю
працездатний — лише форма «Забули пароль?» чесно каже, що доставку не
налаштовано, і пропонує змінити пароль у профілі.

## Встановлення на iPhone

1. Відкрийте адресу застосунку в **Safari** (не в Chrome — на iOS лише
   Safari вміє додавати на екран «Домівка»).
2. Кнопка **Поділитися** → **На екран «Домівка»**.
3. Запустіть із іконки — застосунок відкриється на весь екран, без
   адресного рядка.

Працює офлайн-кеш статики; про відсутність зв'язку застосунок попереджає
банером і не вдає, що зміни збереглися.

## Архітектура

```
src/core/      Фінансовий рушій: дати, гроші, повторення, кредити, прогноз.
               Чистий TypeScript без React і без БД — усе детерміноване
               й покрите тестами.

src/           React-інтерфейс. Прогноз рахується на клієнті одним викликом
               рушія, тож календар, головна й аналітика фізично не можуть
               показати різні числа.

api/           Одна serverless-функція з власним роутером. Вебстандартні
               Request/Response, тож той самий код працює у Vercel,
               у локальному сервері й у тестах.

db/migrations/ SQL. Поточний баланс — не колонка, а view над історією
               операцій, тому подвійне списання неможливе структурно.
```

Детальніше — [`AI_HANDOFF.md`](AI_HANDOFF.md).

## Тести

- **115** unit та інтеграційних: фінансова математика, межі місяців і
  високосні роки, усі типи графіків погашення, дострокове й часткове
  погашення, захист від подвійного списання, ізоляція даних між
  користувачами на рівні PostgreSQL, повний цикл експорт-імпорт.
- **14** наскрізних у браузері на ширині 320px та 430px: сценарій приймання
  з технічного завдання, відсутність горизонтального скролу, навігація,
  теми, маніфест PWA.

Інтеграційні тести виконують справжній SQL через PGlite — PostgreSQL,
скомпільований у WebAssembly. Зовнішня база для прогону тестів не потрібна.

## Безпека

- Паролі — PBKDF2-SHA256, 210 000 ітерацій.
- Сесія — підписаний токен у `httpOnly`-cookie; зміна пароля миттєво
  анулює сесії на всіх пристроях.
- Дані ізольовані на рівні PostgreSQL через Row Level Security: запити
  користувача виконуються під роллю без `BYPASSRLS`, тож навіть помилка в
  коді не покаже чужих записів.
- Секрети зберігаються лише у змінних середовища й ніколи не потрапляють
  у репозиторій.

Застосунок підтримує кількох незалежних користувачів, хоча задуманий як
персональний.
